# 向量响应完成与冷却恢复

2026-10-26 麻辣烫批量恢复出现主、备渠道冷却过期后仍每分钟仅约 4 个成功请求。两个 Redis 记录过期超过十分钟，成功请求仍未清除记录；经有效向量探测并 CAS 删除过期记录后短暂恢复，下一次真实上游错误后复发。

## 原因与变更

OpenAI 向量响应被完整读入内存并通过 JSON/上游错误检查后，设置 Content-Length 写给 Nginx。代理收到完整正文可能立即关闭上游连接，使请求 context 在 Relay 收尾前结束；原判断把所有此类非流式请求按未完成处理，导致成功试探不清理冷却记录。

仅在 OpenAI 向量响应完整校验、写出前 context 仍有效时记录完成标记。Relay 使用该明确事实确认成功，继续通过现有有界脱离取消 context 和故障代次 CAS 恢复渠道；其他非流式协议、提前取消、正文截断或上游错误保持原行为。每次尝试清除标记，旧成功不能污染后续尝试。

## Database / Production Impact

无 DDL、模型/渠道/价格或授权修改。仅修复成功向量请求的冷却收尾，不绕过正在生效的冷却、不放开手动禁用。生产发布须遵守公司 main 源校验和候选平滑切流、在途与账务排空流程；保留现有向量接口 gzip 和全部流式路由。

## Test Plan / Release Notes

新增回归在旧实现重现失败；覆盖完整向量写出后断开、提前取消、截断、非法 JSON、200 内错误、其他非流式协议及尝试间清理。controller/service/openai 三包回归、定向 race 和 vet 通过。线上需观察真实过期记录由正常请求清除、完整向量与消费记录、连续请求吞吐及错误，不注入生产故障。
