# Twork Responses 故障切换

## 行为与范围

`channel_health_setting.soft_failure_cooldown_enabled` 开启时，已校验的 Twork `model-routes-v3` 普通模型模式 `/v1/responses` 使用以下规则：

1. 没有成功粘性时，按剩余可用渠道的最高优先级选择，同优先级保留权重规则。
2. 成功后沿用现有亲和规则的会话键、有效期和 `SwitchOnSuccess`，后续请求优先选择该渠道。
3. 上游服务错误、连接失败、超时、限流、无完成事件的断流触发渠道与模型级冷却。默认沿用现有 30 秒配置；本请求排除已经失败的渠道，按剩余优先级继续，最多沿用现有软故障尝试数配置。
4. 本范围内的临时故障允许覆盖旧 Codex 亲和规则的 `skip_retry_on_failure=true`，成功备用渠道成为新的粘性目标，不需要修改数据库中的亲和规则。
5. 冷却结束后每个渠道与模型最多每 30 秒放行一次真实请求试探；成功清除对应故障代次，失败重新计时。并发报告的新故障不会被旧试探成功清除。无后续流量时不会主动请求上游；未确认的恢复标记最多保留 24 小时。
6. 高优先级恢复后，仍可用的备用渠道会话继续保持粘性，直到原亲和规则失效或再次失败。

固定供应商入口、管理员指定渠道、旧 Codex 有状态请求、compact、非 Responses 协议保持原边界。客户端取消、本地参数/计费问题、鉴权/权限/上游余额错误不触发本次新增的临时冷却；已有硬故障禁用流程保留。关闭软故障开关恢复旧路由策略。

## 流式与计费边界

首个有效事件之前暂存 `response.created` 和 `response.in_progress`（最多 64 KiB），不发送提前提交 HTTP 的心跳，允许上游在此阶段失败时切换。任何其他事件或超过缓冲上限都会提交响应，之后不在本请求中切换渠道。

`response.failed`、`error`、格式损坏和缺少完成事件均作为失败返回。已输出内容时发送 SSE `type=error`，不在流尾拼接普通 JSON；清除失败绑定，下一请求可选备用渠道。正常 `completed` 以及明确因 `max_output_tokens` / `content_filter` 结束的 `incomplete` 保留协议的终态语义。

已输出失败流仍按上游报告的用量结算，缺少报告时沿用文本估算；成功结算后不会重复退还预扣。失败用量不会额外记录为成功性能样本。未输出的失败尝试不单独结算。

## 发布说明

- Database / DDL：无表、字段或生产数据变更。
- Production Impact：需要发布 New API 代码；沿用现有冷却开关、秒数、尝试次数及亲和配置。Redis 用于跨实例冷却和试探限速；关闭 Redis 时为进程内状态。缓存故障按既有策略放行，并记录降级指标。
- Release Notes：普通 Responses 模型调用增加按优先级故障切换、成功粘性、临时冷却与受控恢复；失败流不再误判成功。
- 回滚：回滚至上一发布镜像。新增缓存字段为可选字段，旧代码可忽略；也可关闭软故障开关，但会同时影响既有 Claude 冷却。

## Test Plan

- `NEWAPI_TEST_LOCAL_REDIS=1 go test ./...`：普通优先级、成功后再失败、连续备用、全冷却、失败流、错误语义、固定与旧协议边界及计费相关回归。
- `NEWAPI_TEST_LOCAL_REDIS=1 go test -race ./service -run '^TestResponses' -count=1`：内存与隔离本地 Redis 的恢复试探。Redis 测试只启动临时 Unix socket 实例，不连接生产；需要本机 `redis-server`。

## Manual Acceptance Prompt

发布获授权后，在测试账号的普通 Astra 模型会话发起包含工具调用的任务；用受控测试渠道复现首选渠道 503，核对错误日志的 `use_channel` 按优先级变化且下一轮保持成功备用渠道。再验证流中断仅出现一次终态错误、下一轮切换；冷却结束用新会话验证限速试探，原备用渠道会话不迁回。固定供应商入口失败不得跨渠道。核对消费记录无重复结算、取消请求不写冷却。真实模型验收会产生上游请求及用量。
